# Changelog

All notable changes to gpygap are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the versions follow
[semantic versioning](https://semver.org/spec/v2.0.0.html).

Each entry says what it means for a mirror that already exists, because the people who
run one cannot download a fix.

## [Unreleased]

## [1.1.0] — 2026-11-19

### Added

- **`gpygap scan <directory>`** — work out what a project needs from the project itself and
  write it as a requirements file for `intake/`. It reads declared dependencies
  (`pyproject.toml` including PEP 735 groups and Poetry, `setup.cfg`, `requirements*.txt`)
  and, for a tree that was never packaged, every `import` in every `.py` file, parsed with
  `ast`. The standard library, relative imports and the modules the tree provides itself are
  dropped; what is left is mapped to a distribution by a table of the known mismatches
  (`yaml` → `pyyaml`) and otherwise by PEP 503 normalization (`cocotb_bus` → `cocotb-bus`).
  Lock files are reported, never flattened, because `intake/` already reads them exactly.
  - `--check-index` confirms the guessed names against `upstream.index_url` and reports what
    it does not have instead of writing it as a requirement; `--strict` then exits 1, which
    is what a scheduled job should fail on — the mirror would be one package short.
  - A generated file carries a `# Generated by gpygap scan` header and per-line provenance,
    and a re-scan refuses to replace a file without that header unless `--force` is given, so
    a reviewed and pinned file of your own is safe.
  - [docs/scan.md](docs/scan.md) covers the workflow (scan → review → pin → sync) and the
    four things a scan cannot see.
- `console.setup_console_logging()` for commands that have no run directory to log into.

`scan` and everything else in this release was contributed by Mateusz Chudzik
<matchupikchu99@gmail.com>. The SPDX headers now credit him as author of `scan.py` and
`test_scan.py`, and as contributor to the files he changed.

### Changed

- `intake.requirement_lines()` is now public, so the scanner reads requirements files with
  the same parser as `intake/` rather than a second copy that would drift from it.

### Notes for an existing mirror

Nothing about the mirror, its layout or `gpygap_offline.py` changed; `scan` writes one file
and resolves, downloads and publishes nothing. An existing `gpygap.toml` needs no edit. A
run with no `scan` behaves exactly as in 1.0.0.

## [1.0.0] — 2026-10-15

First release: an offline PyPI mirror of the most popular projects and their dependencies,
for air-gapped networks.

### Added

- **The mirror.** A static PEP 503 index built from the top N PyPI projects
  (hugovk/top-pypi-packages, with a cached fallback), `packages.txt` for your own packages,
  and `intake/` for whole team lock files (`uv.lock`, `pylock*.toml`, `requirements*.txt`)
  mirrored at exactly their locked versions.
- **One resolution per requirement and Python version**, via `uv pip compile --format
  pylock.toml`, so a conflict between two projects can never fail the whole run. Universal
  resolution with targeted healing per platform, and the fixes persisted for later runs.
- **Extras**, resolved one at a time so that extras which conflict with each other
  (`cpu` vs `cuda`) are both mirrored, with version specifiers kept.
- **Wheel building** for every target upstream published no wheel for, in sibling
  pypa `manylinux`/`musllinux` containers with the network off, cached on
  `(sdist sha256, platform, python, builder image)`, so nothing is compiled on a developer
  machine inside the air gap. Windows wheels are built on a Windows runner and adopted from
  `build.external_dir`; the remaining gaps are named in `MIRROR-GAPS.json`.
- **Verification**: an offline install check per requirement × Python × platform against the
  `file://` index, a build check that proves an sdist's build requirements are present, and
  healing rounds. "Complete" means no `missing` and no `missing-deps` after healing.
- **Advisories**: everything published matched against the OSV advisory set into
  `MIRROR-ADVISORIES.json` and a readable `advisories.html`, optionally failing a run.
- **Transfer**: deltas with a version chain and checksums, `MIRROR-SHA256SUMS`, and a
  standalone `gpygap_offline.py` (stdlib only, Python 3.9) for apply, verify and smoke-test
  on the offline side.
- **Retention and safety nets**: rsync semantics with `keep_runs`, `max_prune_ratio`, stale
  resolutions keeping their last good result, and no pruning after a failure that could make
  files look unneeded.
- **Runs in a container** (`bin/gpygap`, `Containerfile`, `bin/gpygap.ps1`), with the uv
  version pinned, so the host accumulates no packages or build tools. `GPYGAP_STORAGE` keeps
  the image store off the system disk.
- **Configuration** in one validated, documented `gpygap.toml`, where an unknown key is an
  error rather than a setting that was silently never read.
- **Reporting**: a per-run JSON report, a console summary and `--plan-only` sizes.
- **Documentation** on Read the Docs, and CI that installs from a real mirror with the
  network switched off inside Debian, Ubuntu, RHEL (UBI), Arch, Alpine and Windows, with
  `--only-binary :all:` so a source build fails the run.
